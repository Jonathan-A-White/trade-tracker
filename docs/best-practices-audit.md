# TradeTracker best-practices audit

Written 2026-10-10 at base commit 9fe24df (version 0.1.27, story mw-vtjxh4.27). Docs only: no behaviour changed.

**What it is.** The Governor asked (Postern general, 2026-10-09 18:37Z) that all his apps be brought up to the best practices the factory keeps. This audit measures TradeTracker against the vault's PWA checklist (`seats/builder/pwa-best-practices/checklist.md`, 31 lines), against each section the checklist points to, and against the rules added to those practices on 2026-10-09 and 2026-10-10 (`changelog.md` of the same folder). Shared code was checked against `seats/builder/library-best-practices/01-when-code-becomes-a-library.md`: the app already imports bsv-kit for the key vault and the grist client (`package.json:18`), and the copies it still carries are listed in `docs/module-map.md` section 4, so no new row is needed.

**What is a PWA here.** All of it. TradeTracker is one React PWA served from GitHub Pages; there is no Android app and no Python server. `grinds/` and `schemas/` are factory data read by the mill, not app code, so no PWA row applies to them. Where a row is n/a, the evidence says why.

**How to read it.**

- Status is `pass`, `fail` or `n/a`. A `fail` is a rule the app does not meet today, or one nothing in the repo proves it meets (said as "Unproven").
- Evidence is a `path:line` that exists in this repo, a command and what it printed, or the reason a row is n/a.
- Size of a fix: **XS** one file and under about 20 lines; **S** one story, under about 100 lines, tests included; **M** one story touching several files and adding tests; **L** more than one story.
- The checklist rows are C01 to C31, in the vault's order. The rows for the newer rules are R01 to R09.
- `bash docs/check-best-practices-audit.sh` checks this file: the row count against the vault's `[ ]` lines, a status and evidence on every row, a fix and size on every fail, every cited `path:line` exists, and the ranked list.
